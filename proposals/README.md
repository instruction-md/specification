# Proposing changes to the first edition

This directory contains the change process for the current first-edition draft.
Earlier draft proposals are not normative inputs or compatibility obligations.

A proposal includes the problem/use case, exact normative change, source and
human/agent representations, registry/schema changes, fallback, diagnostic codes,
security effects, and positive/negative/round-trip vectors. Identify the consumer
roles affected. Status is draft → review → accepted → published.

Before the first edition is finalized, parsing, resolution and serialization
changes need agreement from two independent implementations. Schema checks alone
are not that agreement. Namespaced extensions can evolve independently while
binding exact versions, their own fixtures and the core extension contract.
